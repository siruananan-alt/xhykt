# 页面重复测试及内部计时（2026-10-19）

## 已完成

正常登录的导师会话中反复访问工作台、我的带教、徒弟详情。未修改账号、任务、学习记录、达标线或权限开关。

1. 先采集九次页面/接口耗时。核对最新云函数发现：后续的数值达标规则更新使用了旧的读取范围，导师页面已恢复为 18 份文件读取。
2. 以最新正式备份为基础，保留数值自动判定和导师归属权限，合并回 10 份读取；添加仅 `data.perf === true` 时启用的内部计时。函数版本 `b20261019-internal-timing-v1`。
3. 重复测试发现缓存旧 HTML 缺少新引入的 `readiness-rules.js` 标签，混用新版脚本后可能出现 `ReadinessRules is not defined`，详情页正文不完整。修复方式是把同一份纯规则同步嵌入原有入口 `app.js`，旧页面也能同步获得依赖；同步脚本和一致性测试防止规则分叉。
4. 诊断现在区分接口成功和重绘失败，重绘失败不会再显示为成功加载。
5. 使用修复后的页面重新采集九个有效样本，逐次验证导师名单、详情身份和全部 12 关明细，均通过；控制台没有新增报错。

## 最新有效样本

同一浏览器、同一导师会话，每页三次。单位为毫秒；是小样本观察，不代表所有用户或长时间分位数。

| 页面 | 第一次 | 第二次 | 第三次 | 中位数 |
| --- | ---: | ---: | ---: | ---: |
| 导师工作台 | 2790 | 1285 | 2071 | 2071 |
| 我的带教 | 3700 | 1799 | 861 | 1799 |
| 徒弟详情 | 2919 | 896 | 749 | 896 |

九次均读取 10 份文件，目录初始化为 0 毫秒。函数内部处理为 76～411 毫秒，中位数 127 毫秒；API 总耗时为 700～3291 毫秒。

多数等待发生在函数处理之外。API 总耗时减去内部计时只是近似差值，可能包含请求/响应传输、CORS、网关、排队、平台启动和序列化，不能据此认定其中某一环节就是唯一原因。页面文件首次访问和缓存命中也存在明显差异。

部署后曾单独采到应用初始化 897 毫秒，函数内部总计 1035 毫秒的请求；它不等于测到了平台冷启动耗时。缓存/依赖异常期间的数据仍可辅助分析 API，但不计入有效页面加载结果。
