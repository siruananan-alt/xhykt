# 页面跳转优化（2026-10-19）

每次页面跳转原本会执行目录修补、读取 18 份业务文件；管理员随后再发一次人员列表请求并重复读取整套文件。

- 管理员 `data` 响应合并脱敏人员列表，前端只发一次数据请求。旧云函数仍可兼容。
- 云函数目录初始化在每个运行实例成功后复用；并发初始化合并，失败可重试。
- 同一次请求的文件读取合并，写入后失效；不同请求之间不缓存业务数据。权限和全局开关每次重新读取。
- 管理员的课程管理和权限矩阵分别读取 9 / 6 份文件；三个导师页面读取 10 份，保留学习、任务、解锁、转正登记所需数据。其他页面、学员、旧客户端和写操作仍走完整读取。
- COS 使用持久连接；读取 7 秒、写入 20 秒截止时间覆盖响应体。只有 404 使用默认值，其他错误明确报错。
- 空闲时预取两个导航 HTML，悬停或聚焦时继续预取，总计最多四个。节省流量或 2G 环境禁用；不预取带查询参数的地址，不执行目标页脚本。

验证：`node --test tests/*.test.cjs`；生成云函数后运行 `node scripts/verify-performance-function.cjs <staging>`，使用合成账号与内存存储测试完整请求、角色隔离、实时开关与真实写后失效路径。读取数量是隔离测试结果，不等于线上耗时提升比例。

发布：先下载云函数最新代码备份，用 `scripts/prepare-performance-function.cjs <backup> <staging>` 生成并校验，再从 staging 目录更新函数代码，保留云端配置。版本标记 `b20261019-performance-v1`。前端由 GitHub main 发布。

回退：用发布前备份恢复函数代码；回退本次前端提交。前端兼容旧接口，可分别回退。原始业务数据、密码和环境变量不放入仓库。

## 第二轮：实测与导师按需读取

前端 `?perf=1` 开启加载诊断，同标签页导航继续测量；点击关闭或 `?perf=0` 关闭。默认不开启。只保存开启标记，不上传数据、不记录密码或接口请求体。记录导航、静态资源、接口响应/解析和真实数据重绘后两帧耗时，不代表 LCP；后台标签页样本不可当作前台体验。

2026-10-19，正式站同一浏览器、正常登录的导师会话，单次样本如下。时间为毫秒，各阶段可能重叠，不能相加。

| 页面 | 调整前整页 | 调整前接口 | 调整后整页 | 调整后接口 |
| --- | ---: | ---: | ---: | ---: |
| 导师工作台 | 2249 | 1117 | 1166 | 1137 |
| 我的带教 | 2929 | 2177 | 1762 | 1728 |
| 徒弟详情 | 1755 | 1067 | 4050 | 3238 |

限制：每格只有一个样本，调整后详情页是函数更新后的首个数据请求；客户端不能确定延迟来自冷启动还是网络。调整后工作台和带教页面静态资源已在浏览器缓存，因此不能把整页下降归因于云端改动。工作台接口本身并未更快。当前只能确认读取量下降，不能宣称固定提速比例或所有页面都更快。三个调整后样本说明接口等待仍值得继续拆分测量。

导师按需读取基于最新云函数备份，由 `scripts/prepare-mentor-performance-function.cjs <backup> <staging>` 生成，保留导师转正登记改动；版本 `b20261019-mentor-performance-v2`。隔离集成验证对比完整/精简响应中的课程、任务、进度、达标线与解锁结果一致，并核对其他导师学员的数据不可见。52 项单元测试及集成验证通过，正式页面读取正常、未见控制台报错。

后续优先拆分接口内部初始化、存储与网络耗时，再决定数据库迁移或局部页面切换的投入顺序。
