# 页面跳转优化（2026-10-19）

每次页面跳转原本会执行目录修补、读取 18 份业务文件；管理员随后再发一次人员列表请求并重复读取整套文件。

- 管理员 `data` 响应合并脱敏人员列表，前端只发一次数据请求。旧云函数仍可兼容。
- 云函数目录初始化在每个运行实例成功后复用；并发初始化合并，失败可重试。
- 同一次请求的文件读取合并，写入后失效；不同请求之间不缓存业务数据。权限和全局开关每次重新读取。
- 仅管理员的课程管理和权限矩阵分别读取 9 / 6 份文件；其他页面、学员、导师、旧客户端和写操作仍走完整读取。
- COS 使用持久连接；读取 7 秒、写入 20 秒截止时间覆盖响应体。只有 404 使用默认值，其他错误明确报错。
- 空闲时预取两个导航 HTML，悬停或聚焦时继续预取，总计最多四个。节省流量或 2G 环境禁用；不预取带查询参数的地址，不执行目标页脚本。

验证：`node --test tests/*.test.cjs`；生成云函数后运行 `node scripts/verify-performance-function.cjs <staging>`，使用合成账号与内存存储测试完整请求、角色隔离、实时开关与真实写后失效路径。读取数量是隔离测试结果，不等于线上耗时提升比例。

发布：先下载云函数最新代码备份，用 `scripts/prepare-performance-function.cjs <backup> <staging>` 生成并校验，再从 staging 目录更新函数代码，保留云端配置。版本标记 `b20261019-performance-v1`。前端由 GitHub main 发布。

回退：用发布前备份恢复函数代码；回退本次前端提交。前端兼容旧接口，可分别回退。原始业务数据、密码和环境变量不放入仓库。
